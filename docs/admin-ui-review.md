# 后台管理系统 UI 评审报告

- 评审对象：TypechoEdge 后台（`/admin`，admin.css 2026-11 重设计版）
- 评审日期：2026-11-11
- 评审范围：登录、仪表盘、文章列表、编辑器、分类/标签、评论、附件、站点设置、备份恢复、回收站、安全设置
- 方法：Chromium 1366×900 / 375×812 实际渲染度量、DOM/CSS 静态审计、键盘与弹窗交互测试、截图归档
- 截图：`docs/admin-ui-audit/`

## 一、结论摘要

后台已经具备一套**成熟的基础视觉系统**：zinc 中性色 + 靛蓝焦点色、统一的圆角/阴影/动效令牌、深浅主题、清晰的页面标题锚点、友好的空状态文案。整体方向不需要推翻。

当前主要缺口不在"好不好看"，而在**系统性收口**与**无障碍硬指标**：

| 维度 | 评价 | 关键问题 |
|---|---|---|
| 视觉层次 | 良好 | 仪表盘 hero 权重过强；列表危险操作权重偏高 |
| 一致性 | 中等 | 字号 17 种、圆角 15 种、断点 19 个、颜色仍有 98 处硬编码 |
| 无障碍 | 不达标 | 表单标签未关联、控件边界对比 1.28:1、侧栏小字 2.28:1、无 h1、触摸目标 27–30px |
| 组件规范 | 部分成型 | 按钮有 3 套尺寸但缺统一语义；弹窗焦点管理缺失 |
| 功能可靠性 | **有阻断问题** | 危险操作确认弹窗实际未生效（脚本先于弹窗执行） |

建议按「先修可用性阻断 → 再补无障碍硬指标 → 最后做令牌收敛与视觉打磨」推进。

P0（R1–R3）与 P1（R4–R8、R10–R12）共 **11 项已全部修复并通过回归**；另外随本次一并修复了 P2 的 R9。P2 的 R13–R17 仍为打磨建议。修复明细与前后指标见第七节。

## 二、值得保留的部分

- 颜色、圆角、阴影、动效均已有 CSS 变量，深浅主题切换完整，`color-scheme` 正确声明。
- 全局 `:focus-visible` 焦点环统一为 2px 靛蓝 + 2px offset，键盘焦点可见。
- 侧栏当前项使用 `aria-current="page"`；面包屑有 `aria-label`；图标普遍 `aria-hidden`。
- 危险色使用克制，仅删除/危险确认使用红色；空状态有引导文案（"还没有文章，去写第一篇吧。"）。
- 编辑器、表格、设置页均有针对性的移动端适配；`prefers-reduced-motion` 有降级规则。
- 页面标题使用 3.5px 靛蓝竖条建立锚点，视觉记忆点明确。

## 三、问题清单

### P0 — 阻断级（建议本周修复）

#### R1 危险操作确认弹窗未生效

- **证据**：后台 HTML 中内联脚本位置 `12639`，`.ui-modal` 位置 `21400`，脚本先执行时 `document.querySelector('.ui-modal')` 为 `null`，`if (uiModal)` 整体跳过，`data-confirm` 的 `submit` 拦截从未绑定。
- **实测**：在评论管理点击"删除"，页面直接提交并删除（评论数 7 → 6），没有出现确认框；回收站中"清空/永久删除"等 `data-confirm` 表单同样不受保护。
- **影响**：误删风险；"清空回收站"属于不可恢复操作。
- **建议**：把 `.ui-modal` 节点移到内联脚本之前；或改为 `DOMContentLoaded` 后查询 / 事件委托绑定 `document.addEventListener('submit', ...)`，并在弹窗节点不存在时延迟初始化。

#### R2 表单控件普遍没有可访问名称

- **证据**（可见字段中无 `label` 关联的数量）：
  - 站点设置 10+、备份恢复 10、编辑器 9、分类/标签 7、安全设置 6、附件 1
  - 模板结构为 `<label>状态</label><select name="status">`，label 与控件是兄弟节点且无 `for`，屏幕阅读器无法关联
  - 编辑器的 `field_thumb / field_abstract / field_mode` 只有 placeholder，没有 label
- **影响**：屏幕阅读器读出"组合框"而无字段名；语音控制无法按名称定位。
- **建议**：统一 `id` + `<label for>`；一组控件用 `fieldset/legend`；自定义字段补独立 label；placeholder 不作为标签。

#### R3 输入框边界对比度仅 1.28:1

- **证据**：输入框 `border-top-color: rgb(227,227,232)`、背景 `rgb(255,255,255)`，对比 **1.28:1**（设置页 8 个控件一致）。
- **标准**：WCAG 1.4.11 非文本对比要求 UI 组件边界 ≥ 3:1。
- **影响**：低视力、强光环境下难以分辨输入框边界。
- **建议**：新增 `--control-border`（如 `#8f8f9b`，对白底约 3.2:1），输入框使用该令牌；hover/focus 再提升。

### P1 — 高优先（下一迭代）

#### R4 侧栏辅助文字对比度不足

- **证据**：分组标题"内容 / 系统"与版本号 `TypechoEdge v1.6.12` 为 11px + `--ink-4 (#a7a7b3)`，对 `--surface-2` 背景对比 **2.28:1**。
- **建议**：改用 `--ink-3`（约 5.5:1）并提升到 12px；`--ink-4` 仅保留给禁用态/装饰。

#### R5 所有后台页面缺少 `<h1>`

- **证据**：10 个后台页面 `h1 = 0`，主标题为 `<h2>`（仪表盘"欢迎回来"、列表页"管理文章"）；h1 只存在于登录页。
- **影响**：文档大纲从 h2 开始；屏幕阅读器按标题跳转时缺少页面级锚点。
- **建议**：页面主标题改为 `<h1>`（沿用现有 `.main > h2` 的视觉样式），卡片标题降为 h2、小节 h3；或增加视觉隐藏的 `<h1 class="sr-only">`。

#### R6 触摸目标偏小

- **证据**：`.btn` 38px、`.btn.sm` 30px、`.btn.mini` 27px；编辑器工具条 30px；移动端（375px）未放大，"通过/删除"仍为 43×27。
- **建议**：桌面默认 36px、紧凑 32px、表格行内 28px；`@media (pointer: coarse)` 下统一提升到 44px，并增大图标按钮的点击区域。

#### R7 确认弹窗缺少完整焦点管理

- **证据**：弹窗 `role="dialog" aria-modal="true"`、打开时聚焦取消按钮、Esc 可关闭（在修复 R1 后生效），但没有焦点陷阱、背景未 `inert`、关闭后未归还焦点。
- **建议**：打开时对背景容器加 `inert`；Tab/Shift+Tab 循环在弹窗内；关闭后把焦点还给触发按钮。

#### R8 表格与跳转语义缺失

- **证据**：表头 6 个 `th`、`scope` 数量 0；页面没有 skip link，主内容容器 `.main` 没有 `id`；分页组件未设置 `aria-label`。
- **建议**：`th scope="col"`；增加"跳到主要内容"链接（首个 Tab 可见）；`<main id="main">`；分页 `nav aria-label="分页"` + 当前页 `aria-current="page"`。

#### R10 设计令牌没有覆盖字号、间距与断点

- **证据**：字号 17 种（含 11.5 / 12.5 / 13.5 / 14.5 半像素）；圆角 15 种；`@media` 19 个（760/1080 多次重复）；硬编码颜色 98 处；`!important` 8 处。
- **建议**：见《后台组件规范》的令牌表，将字号收敛为 7 档、间距统一 4px 基准、断点收敛为 4 档，颜色全部走语义令牌。

#### R11 按钮尺寸体系不统一

- **证据**：同一表格行内混用 `.btn.sm`（30px）与 `.btn.mini`（27px）；`td a.btn` 用 `margin-right: 6px` 而非 `gap`。
- **建议**：统一 `--control-h-sm/md/lg`，表格操作区用 `display:flex; gap:8px`，危险按钮默认 ghost、hover 再显红。

#### R12 移动端文章表格信息密度低

- **证据**：375px 下 6 列表格压缩到 309px 宽，单行高度 231–253px，`tr` 为 block 布局；阅读一屏只能看到 2–3 条。
- **建议**：窄屏改为卡片列表：首行标题 + 状态徽标，次行时间/评论数，操作按钮独占一行；隐藏 ID、作者等次要列。

### P2 — 打磨项

- **R9**：主题切换按钮缺少 `aria-pressed`（`aria-label` 已由 JS 动态更新，这点做得正确）。
- **R13**：空状态只有文案，没有可点击的下一步动作（建议加"写第一篇 / 去审核"按钮）。
- **R14**：列表每行红色"删除"与"编辑"同权重，建议默认 ghost + 更多菜单，确认文案写明后果（"删除后进入回收站，可恢复"）。
- **R15**：设置页表单很长，保存按钮在底部；建议 sticky 底部操作栏或顶部保存。
- **R16**：仪表盘 hero 深色渐变是视觉最强元素，但主任务（发布/审核）分散；建议 hero 只承担身份与站点状态，主 CTA 唯一化。
- **R17**：成功/失败反馈目前是 URL 参数渲染的文本（如"操作成功"），建议统一 Toast，`role="status"` / `aria-live="polite"`。
