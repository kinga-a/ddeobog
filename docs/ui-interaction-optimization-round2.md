## 三、重点说明

### U1 未保存离开

后台是 SPA 局部刷新，浏览器 `beforeunload` 不会触发，必须在导航函数里拦截。建议：

- 编辑器/设置页维护 `dirty` 标记；
- 点击侧栏、面包屑、返回时，若 dirty → 复用现有 `.ui-modal` 弹窗："有未保存的修改，离开将丢失。取消 / 放弃并离开"；
- 保存成功后清除 dirty。

### U2 保存按钮位置

设置页 1741px 高、保存按钮在 1588px，是当前最明显的效率问题。建议把保存按钮放进 sticky 底栏（`position: sticky; bottom: 0`），并保留顶部标题右侧的次入口。

### U3 评论提交

当前按钮是普通 `<button type="submit">`，点击后页面等待服务端响应，期间无任何状态。建议：

- 提交时 `disabled` + 文案"发送中…" + 14px spinner；
- 成功后按钮恢复，评论区插入新评论；
- 失败时显示可读错误并保留输入；
- 移动端按钮高度 ≥44px。

### U4 危险确认

现有弹窗焦点与 Esc 已修好，但按钮语义仍弱。建议按动作命名（"删除评论"），危险按钮使用红色实心（规范中的 `danger-solid`），正文说明"删除后进入回收站，可恢复"或"不可恢复"。

### U6 反馈统一

后台保存目前依赖 URL `?msg=ok` 在页面顶部渲染"已保存"；长页面保存后虽然会滚回顶部，但缺少非阻断反馈。建议：

- 成功：右下角 Toast，`role="status"`，4 秒消失；
- 失败：Toast `role="alert"`，手动关闭；
- 保留页面内提示作为兜底。

## 四、不建议改

- **404 视觉**：你此前明确表示新版不好看，已恢复原样，本轮不再提。
- **首页无限滚动**：实测点击"查看更多"可从 10 条加载到 13 条，功能正常；只缺加载反馈（U6），不是失效。
- **图片灯箱**：5iblog 主题当前未内置，属于增强项，优先级低于 U1–U7。

## 五、建议实施顺序

1. **U1 + U2**：数据丢失与长表单效率，收益最高。
2. **U3 + U4 + U6**：评论提交状态、危险操作语义、统一反馈。
3. **U5 + U7**：列表检索/批量、登录页可达性。
4. **U8–U13**：体验打磨，按使用频率取舍。
